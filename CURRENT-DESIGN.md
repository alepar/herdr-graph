# Current graph design — updated 2026-10-17

## Identity and scope

- Flat teamspace = Herdr workspace; seat = tab when activated; clone = pane; native sessions occupy clones. Seats may exist before activation without tabs. Multiple clones may occupy one seat.
- Seat IDs independently identify seats, including fresh seats without templates. Optional template/declaration references supply defaults/provenance. Seat ID is not derived from template or hydration ID; no extra per-seat hydration identity is needed.
- Graph tracks organization, relationships, templates/rules and its own operation/reconciliation bookkeeping. Project work remains in Beads, sessions and wikis. Attribution includes teamspace/seat/clone/native session/transcript; bead closure is not independent evidence of completion or acceptance.
- Beads' Dolt state is orthogonal to graph's Git-tracked files; graph does not coordinate Beads database writes with its Git commits. Only agents explicitly mutate Beads. Seat creation/retirement does not change beads; successors discover inherited work by teamspace/seat/clone labels. Beads tracks plans sent into execution, milestones and published artifacts, with native-session/transcript attribution retained where applicable.
- Human-browsable folders follow teams/seats/clones. Shared seat and clone state are separate. Memory prose and role-specific behaviors remain opaque to graph. Mechanical session/transcript indexing and processing requests are now within scope; semantic summarization is delegated.

## State and reconciliation

- User-directed plan/confirm/apply flow: every requested change displays a detailed plan for user confirmation, then applies exactly that approved change. A stale plan requires a new plan and confirmation. Approval covers the requested change and its downstream effects; progress and retries within that plan proceed automatically. Changed assumptions or different effects require renewed confirmation; unrelated activity does not invalidate the plan. Specify observation/bookkeeping representation and how automatic summarizer activation fits approved workflows without granting unbounded activation authority.
- One graph-instance Git repository and shared checkout. Plugin alone writes and commits through a durable journaled queue with one serialized worker. Each graph mutation is a conditional, recoverable transaction: validate on admission where practical and recheck relied-on state when applying. Unrelated intervening changes may proceed; conflicting edits return to the requesting agent with an explanation. Graph does not merge competing prose or intentions.
- `/seat` and reconciliation read a complete committed revision while the writer prepares changes. Commit each multi-file mutation together; distinguish durable queue admission, graph commitment and external reconciliation. Operation identity lets restart recovery determine whether a mutation committed, resume unfinished work and avoid applying a committed mutation twice. Exact revision/precondition representation, committed-read access and journal/commit recovery mechanics remain implementation design.
- Reconciliation is separate: state changes, Herdr events and periodic checks trigger it. Graph commits desired state first, then drives Herdr/threads. Observed manual changes feed graph state through the writer.
- Follow latest committed intent; preserve superseded history, stop obsolete retries, reconcile already-performed effects toward current intent. Missing some manual actions is explicitly acceptable.
- Retry transient external failures automatically with backoff; inspect uncertain outcomes before non-idempotent retries. Requests needing revision notify/remind the responsible agent and link replacements. Explicit cancellation/reassignment supported. Retiring a requester preserves unresolved graph operations for discovery; instance rules choose a successor.
- Cancel an uncommitted queued request without applying its mutation. After commitment, cancelling remaining effects requires a superseding mutation specifying replacement desired state; ambiguous replacements return to the requesting agent. Preserve already-performed effects in history and reconcile toward the replacement, without silently undoing the original operation. Cancellation must not leave a hidden suppression flag competing with desired state.
- Delayed action instructions carry their originating operation and relevant revision. Recipients check current applicability before acting; an obsolete whole-seat leave instruction must not become a fresh voluntary clone opt-out. Exact message/API representation remains to specify.
- Closure retirement follows containment: a pane retires its clone; a tab retires its seat and remaining clones; a workspace retires its teamspace and all remaining seats/clones, including dormant seats. Native-agent exit with the pane retained ends occupancy only. If last-pane closure also removes the tab, the resulting tab closure retires the seat. Archive state and attribution; never-activated absence is intentional, and disconnected/ambiguous observations mark runtime availability unknown rather than retiring objects.
- 2026-11-05: the node manager seat is exempt from direct-closure containment retirement. Closing its pane, tab or workspace never retires it, its clones or its teamspace; reconciliation reopens it (recreating the workspace first when needed). Other seats in a closed workspace or tab still follow containment retirement. The decision is made by `CascadeMutation` at apply time, per clone: classification only reports which clones' panes survived the closure, the node manager ends and absents just its non-survived clones (a survivor stays bound) and every other seat retires all its clones. `moved_out` never decides workspace placement: a pane in another teamspace's workspace does not place this teamspace's.
- Record a closure cascade as one action with provenance and the descendants it actually retired, distinguishing previously retired objects for undo. Correlate graph-issued closures with observations to avoid duplicate retirement. Graph reconciles lifecycle thread-membership cleanup after occupants disappear while preserving messages and attribution. Exact observation qualification and transport cleanup mechanics remain to specify.
- Cross-tab clone moves initially require destination-seat reload; old transcript/context remains but applicable graph state changes. Eventual clone transfer preserves work history and changes scope/system threads.

## Templates

- Reusable seat templates are shared across team templates; there is no separate profession-role object layer. A seat template supplies reusable instructions/runtime defaults, while a team member references it and adds responsibility, startup, overrides and participation. Separate applications create independent seats unless an actual seat is explicitly reused.
- Runtime precedence: seat instance override > team member override > seat template default > team template default > graph default > applicable built-in fallback. Load seat-template instructions, member specialization and instance context alongside scoped rules through `/seat`. Implemented with shared TemplateId and `kind = "team" | "seat"`; omitted kind remains team. Team members use typed `seat_template` references and `responsibility`. `/seat` returns canonical seat context plus the instruction stack rendered verbatim from the committed revision (see Bootstrap); this supersedes the earlier "does not synthesize prose" rule. Instruction files outside templates change only through `plan instructions set|clear <global|teamspace|seat> …` (closed file set `rules/<name>.md` and seat `AGENTS.md`, one admissibility predicate shared by plans, the renderer and doctor `instruction_files`, unified diff in the plan, undo via `InstructionsKind`, `repair_required` when the file drifted); template and section instructions keep `plan template edit` and `plan seat override --section`. `herdr-graph instructions show` reads the committed head without a daemon. `content write` is removed (stub exits 2).
- Existing summarizer/system/cron/dispatcher markers represent operational duties, not professions. Canonical configuration is `system_duty` / `SystemDuty`; existing `role` fields and `--role` remain read aliases, and unused `role_ref` is ignored. Summarizer discovery and summary eligibility are preserved.
- Live references: defaults AND structural edits affect current instances immediately through reconciliation, including model/harness changes rather than deferring them to next activation. Requested changes follow the detailed plan/confirm/apply direction; undo handles accidental mass changes. Explicit instance overrides persist across template changes. Named copies (v1/v2) support experiments; no hidden version pinning/upgrade layer. Show required session replacements in the approved plan, preserve history, and resume where the harness supports it. Reviewed effects include definition revisions, exact changed values and required occupied-clone replacements, including surviving canonical seats after application withdrawal. Native history/resume uses existing harness capabilities.
- Instance additions and exclusions persist. Retirement of a template-declared member excludes it locally so it is not recreated; independent additions survive template edits.
- Template member IDs survive renames and are preserved for corresponding roles in copied templates. Instantiated seat IDs survive renames, retirement/resurrection and explicit template switches. Grouped action records reference created/reused seat IDs for undo, not seat-ID derivation.
- Each template application has a small durable composition record: stable application ID, editable name, live template reference, template-member-to-seat mappings, additions, exclusions and relationship contributions. Application identity scopes repeated composition and collective operations; seat IDs remain independent and no nested teamspace is introduced. Explicit reuse is recorded in each participating application. Group operations use current membership; hydration actions remain historical undo provenance.
- Member correspondence preserves instantiated seats across an application's template switch; exclusions are application-scoped. Retiring or undoing an application withdraws its live contribution and retires only members still exclusive to it, including members created later by live-template edits. Preserve pre-existing members and those reused elsewhere; retain relationships with another application or independent contribution. Ambiguous later edits/configuration dependencies require an agent repair plan. Direct tab/workspace closure still follows containment retirement.
- Re-added template members retain instantiated identity when correspondence is clear, respecting local exclusions. Elaborate exact member-removal transitions consistently with contribution/dependency rules; blanket retirement of all derived seats was not approved.

## Bootstrap and system-duty seats

- Instruction rendering: `/seat` (`seat --json` `instructions`, `seat --instructions` without a daemon) and the SessionStart hook render the instruction stack verbatim from the committed revision, never the working tree, in the order global rules, teamspace rules, template parts (seat template, team root, member `AGENTS.md` and `responsibility`), seat `instructions_sections`, seat rules, seat `AGENTS.md`; later sections win. The hook output is capped at `HOOK_RENDER_CAP` (9000 bytes): whole parts are kept from the most specific outward, the first part that does not fit and everything more general is omitted, a marker line names them and points to `seat --instructions`. `seat --json` `paths.data` lists files that are context only (never instructions) and `paths.clone_record` replaces `paths.clone_files`. A live or resumed session may hold earlier instruction text until its context is reset.
- Apply ask rule: `setup claude` adds `Bash(herdr-graph apply:*)` to `permissions.ask` (and the absolute-binary variant), `setup codex` writes `rules/herdr-graph.rules`; both are recorded in the setup manifest and removed on uninstall. `doctor` `harness_gate` warns when a harness with the owned hook lacks the rule. The gate is cooperative: prompt-skipping modes, rewrapped invocations, direct daemon-socket calls, edited harness settings, direct git commits, cleared marker variables with a faked terminal and harness-native project instruction files are accepted residual vectors. The `[y/n]` prompts refuse under `CLAUDE_CODE_SESSION_ID`, `CODEX_SESSION_ID`, `CODEX_THREAD_ID` or `HERDR_GRAPH_SEAT`.
- Summaries: `request complete <rq> --summary-from <file> --covered <a-b>` writes the summary into the source seat's `summaries/` and completes the request in one commit; it stays a bookkeeping request.
- One `/seat` entrypoint. Proposed marker HERDR_GRAPH=1 enables session-start instructions to run it; resolve actual binding separately. Agent discovers/reads applicable state, latest templates, overrides and rules itself. No separate plugin-generated semantic brief.
- Prefer attributed threads communications. Threads 0.2.9 no longer injects Codex `--no-daemon`; optional HERDR_THREADS_CODEX_OPTS/HERDR_THREADS_CLAUDE_OPTS are upstream managed-launch settings. Graph uses its own harness launch path and explicit graph arguments; no native launch behavior was validated in this integration. See the release handoff for source-versus-runtime evidence.
- Summarizer is an ordinary system-duty seat from a minimal supplied template. Graph detects transcript processing work, activates an absent occupant of an active seat through ordinary activation under the approval contract, and posts durable thread requests. Explicitly retired seats require explicit resurrection intent; pending work cannot override retirement. No special activation flag or plugin-managed model worker pool.
- Threads is the selected reliable request queue with ACKs. The summarizer ACKs after dispatch to a subagent; an ACK does not mean processing succeeded. Role instructions track successfully processed transcripts and periodically scan for leftovers after failures. Cadence and scheduling mechanism remain to specify; this is role-owned recovery, not a plugin worker pool. Other ruminate/dream/rule extraction behavior remains opaque and extensible.
- A seat parameter enables/disables transcript summaries. The `summaries` parameter and effective system duty control source eligibility; ordinary seats default to summaries enabled, while system/cron/dispatcher/summarizer duties default to summaries disabled to prevent recursive source processing; explicit summaries configuration follows runtime precedence. This controls source eligibility separately from activation of a destination summarizer.
- Shared request/result contract tracks transcript identity, processed-through coverage and output references. Resume may append processing work; explicit successful results remain distinct from dispatch ACKs. Pending requests survive crashes. Each processing unit identifies a transcript and fixed input boundary. Record successful coverage and its output reference separately from dispatch; out-of-order results cannot erase newer coverage or conceal gaps. Missing input remains explicitly unresolved. Exact role-tracking/graph-result integration, deduplication and session closure detection remain implementation design.

## Threads and policy

- Graph owns whole-seat participation intent and clone-specific choices; threads owns actual participant memberships/receipts. Each native participant maps to a clone. Future clones inherit whole-seat intent, not all individual subscriptions.
- Public seat/team system channels, required invitations accepted explicitly before becoming unleaveable. Service identity uses one registered persistent UDS connection under cooperative trust; durable author survives reconnect, connection authority does not. Never fabricate native acceptance/ACK.
- Participation follows the clone's recorded threads seat (`CloneRecord.threads_seat`), not its occupant: required invitations are issued as soon as the seat is known and survive agent exit, `/clear` and relaunch on the same pane. A Required invitation is released only on seat succession or when its want disappears (opt-out, channel removed); retiring a clone releases nothing, memberships end at purge. Acceptance is not liveness; the occupant on an invitation link is attribution only.
- The graph is pinned to herdr-threads v3.1.0 (`third_party/herdr-threads`; `service_session_v3`). Every active clone has a continuity-key reservation, recorded as `CloneRecord.key_reservation` (`{key, seat?, at}`; the key is the clone's `cl_` id). The `threads.reserve_key` want issues the seatless `ReserveContinuityKey{key}` for an active clone with no recorded reservation, and records the answer through ThreadsSeatAssignment (`RecordReservation`); an unreachable threads records nothing and retries under the same operation key, and a threads `Conflict` records nothing. The want also backfills clones that predate the key. It binds no key to a seat: binding a key to the clone's `threads_seat` (including the relink after a seat succession) belongs to the key-link want (hg-66u.68). A succession leaves the reservation record in place.
- Key-conflict alert: a `SeatInspect` result whose `continuity_key.conflict` is set (threads holds the clone's key against another pane) reads as `KeyConflict{pane}` unless the seat is retired (retirement wins). The clone becomes Unknown, is never launched, and its committed `seat_fact` carries the alert. `status` lists each such clone under `clones.key_conflicts` (`{clone, name, pane, remedy}`, `pane` is `unknown` when threads named none). Operator resolution, as the status text says: `close the stray pane <pane>, or retire/purge clone <name>; threads clears the hold at the next check-in`.
- Whole-seat ordinary leave updates intent and notifies other clones to leave themselves; actual completion can lag. System-channel lifecycle cleanup differs from voluntary leave.
- Hierarchy, fences, escalation and termination approval remain instance instructions. Encourage seats for durable user-facing responsibility, clones for durable parallel conversations, subagents for temporary collaboration. Precise native-session termination versus retirement approval scope remains open.
- Threads extension was designed and handed off separately. Current threads repo is `/Users/alepar/AleCode/herdr-threads`; old implementation worktree has been removed. Current designs are under `docs/design/`; historical run evidence is archived there or in tag `archive/herdr-threads-run-2026-09-26`. Inspect current artifacts before claiming implementation status.

## Undo

- Dedicated CLI, separate from automatic `/seat`. List recent actions newest first, let user select, show a concrete undo plan, then [y/n]. Adopt the command's current terminal pane only when restoring a runtime presence; identify the restored clone it becomes and other panes to reopen. Previously dormant seats remain dormant.
- Undo reopens each restored clone's own tab in its original workspace and never adopts the caller's pane: restored clones commit with no runtime, and the reconciler creates the pane and writes it as the clone's binding. The caller's pane is left in place unless the undo itself retires it; in that case, preview its closure, persist the operation and provide its ID before closing it; completion remains discoverable elsewhere. A restored clone that holds a threads seat commits a Restore intent. With a continuity key bound to the seat, a pane close retires the seat reversibly (D2) and undo or resurrection un-retires the same seat: the seat id, its memberships and their acceptances are kept, nothing is re-invited, and the resume driver makes the one keyed launch that reattaches it. Seat succession is the exception, only for a final-retired seat: a keyless pane close (no bound key, for instance a shell that rejected the export before the key was linked) or a seat the operator retired explicitly. There the reopened pane is resolved to a fresh seat, the key is relinked to it by the key-link want, and the memberships are re-invited and accepted once more. A reversibly retired, live or unresolved seat is never succeeded. The only finalizers of a reversible retirement are the graph's `FinalizeRetirement` at `clone purge` and an explicit operator retire; threads has no timer that finalizes it. An export-rejected clone gets its key bound threads-side but its agent may not present it: with a resumable session the resumed agent reattaches the unretired seat by its native session; without one `status` lists the restore under `clones.stuck_restores` (fix the pane shell, start the agent manually, or retire the clone).
- Initial scope includes closures/retirements, hydration and template updates. Grouped actions record before/after/provenance. Undo creates compensating graph mutations and reconciliation; preserve history and unrelated work.
- `clone purge <clone>` (plan/confirm) ends a retired clone's undo window: undo and seat resurrection no longer bring it back. There is no automatic retention timer. A clone that held a threads seat leaves an inert tombstone (identity plus `Finalize{seat}`) until threads finalizes the retirement; a seatless clone with a recorded key reservation leaves a `ReleaseKey{key}` tombstone instead, until the key is released; a seatless, unreserved clone's record is removed. `status` lists retired-unpurged clones under `clones.retired_unpurged`.
- Hydration undo retires its application to stop live-template generation, then removes that application's contributions using current membership and dependencies. Include later template-created members; retire only those still exclusive to the application. Preserve pre-existing or subsequently reused objects and relationships with another independent contribution. Show preserved and retired objects in the preview; ambiguous dependencies go to agent repair planning. Template undo reverses the edit while preserving unrelated later edits and instance overrides. Preview all current affected instances, even those created later.
- Conflicting later edits are explained and sent to an agent for repair planning; do not guess. Native session resume versus fresh launch, exact multi-object placement mechanics and dependency conflict checks remain to specify.

## Manager seats and the seat failure path — 2026-11-05

- Manager pointers: `SeatRecord.manager`, `TeamspaceRecord.default_manager` and graph.toml `node_manager_seat`, all optional and serde-defaulted (no schema bump). A seat's effective manager is its explicit `manager`, else its teamspace's `default_manager`, else the node manager (a seat never manages itself). Retired seats are transparent: resolution continues through the retired seat's own effective manager. A missing or retired `node_manager_seat` is treated as unassigned, not as an error; an explicit `manager` naming a missing seat, or a cycle, is an integrity error. `model::manager` owns resolution; nothing else reads the raw pointers to decide who manages whom.
- Pointers change only through plans: `plan manager set <seat|teamspace> <manager-seat>`, `plan manager clear <seat|teamspace>` and `plan node-manager set <seat>`. None of them is an undoable action. `make_plan` refuses any plan that would leave a manager chain cyclic.
- Node manager: the first seat created on a graph that has none is assigned the role (existing graphs are never auto-assigned). It must be Active, and no plan can retire it, deactivate it or its last live clone, or move its placement; to retire or move it, first move the role with `node-manager set`. Direct closure never retires it: see the 2026-11-05 observation line above, which this section does not restate; reconciliation reopens it. `node-manager set <seat>` activates a dormant target as a listed effect, rewrites the old node manager's direct reports (seats whose explicit `manager` was the old one, teamspaces whose `default_manager` was the old one) to the new node manager, sets the old node manager's own manager to the new one, and clears the new node manager's own manager.
- Node manager moves (2026-11-06, B11): Herdr moves panes (`pane.move`: to another tab, `--new-tab [--workspace]` or `--new-workspace`, in every supported version 0.9.1 to 0.9.5) but has no cross-workspace tab move (`tab.move` only reorders). When an out-of-plan pane move empties the node manager's home tab and its surviving panes share one tab no other seat owns or holds a clone in, that tab becomes its tab: `build_ops` passes it as `seat_follow` and `MoveMutation` adopts it when the seat is the live node manager, instead of setting `moved_out`. Otherwise `moved_out` is set as for any seat and missing clones reopen in a fresh home tab. The observer warns, the moved clone gets `reload_required`, and nothing is moved back.
- Reparenting on retirement: every retirement route (plan `Retire`, `ApplicationRetire`, the observed cascade and undo-driven retirement) goes through `do_retire_seat`, which rewrites each live seat `manager` and each teamspace `default_manager` that named the retiring seat to the retiring seat's nearest surviving manager. Each rewrite is recorded as `{holder, field, old, new}` in the action record, and plan previews list the same rewrites as effects. Undo of a `Retire` or `ApplicationRetire` restores each pointer only where it still holds the value the reparent wrote; pointers changed since are left and listed in the undo plan.
- Unassigned warning: while `node_manager_seat` is unset (or names a missing or retired seat) and a non-retired seat exists, every graph command except `init`, `setup`, `daemon` and `seat --hook-prompt` prints `herdr-graph: warning: no node manager is assigned; run herdr-graph plan node-manager set <seat>` to stderr. It reads the committed graph for the warning only and is not a daemon fallback.
- Integrity errors and exit codes: a reference that does not resolve (previously dropped silently) now fails with `StoreError::Integrity`, carried as `IpcErrorCode::Integrity` by `seat.resolve`, `who` and plan creation; only `seat_reply` adds the node manager to report it to. Plan-time hook-size warnings (`cap_warning`) turn it into a warning so a broken seat never blocks unrelated or repairing plans. `cli::daemon_error` maps every daemon-calling command: exit 2 (no instance configured, or not inside a Herdr pane), 5 (graph daemon unavailable, including still starting or version mismatch; retry later), 6 (graph integrity error; not transient, report it to the node manager), 1 for other rejections. For `/seat`, 5 and 6 add that the seat context is not loaded.
- Daemon-free fallbacks removed from `who`, `ops`, `request` and `undo`: an unreachable daemon is exit 5, not a direct read of the graph. `status` keeps its own fallback as the operator's diagnostic. `show`, `list`, `path`, `instructions show` and `seat --hook-prompt` remain daemon-free readers by design; `show` maps a manager-chain integrity failure to the same exit-6 text.

## Clone location after the threads seat identity work — updated 2026-11-07

One rule per clone kind locates a clone; nothing else does. A clone with a `threads_seat` is located only by SeatObservation: Resolved binds it to threads' pane, Unresolved, KeyConflict and a lost seat leave it Unknown, Retired retires it, and an unreachable threads service holds the binding SeatObservation last wrote (the matcher links a seated clone only to the pane that binding names in the snapshot's own incarnation, never by token, terminal id, cwd or native session). A clone without a `threads_seat` (shell-harness clones, agents that never check in) is located by its graph token, else by the pane id its committed binding names in any incarnation (Herdr preserves pane ids across a restart, as it does tab and workspace ids), unless that pane carries another clone's token; an absent id is Unknown, never recreated or retired. The create correlation (journal live ref, create nonce) stays only for the pane the graph itself is creating. The planner's `LiveIndex::pane` follows the same rule. The old terminal-id, cwd, native-session and rebind-adopted passes are deleted ([parity record](docs/superpowers/runs/2026-11-04-threads-seat-identity/parity.md), S1 waiver).

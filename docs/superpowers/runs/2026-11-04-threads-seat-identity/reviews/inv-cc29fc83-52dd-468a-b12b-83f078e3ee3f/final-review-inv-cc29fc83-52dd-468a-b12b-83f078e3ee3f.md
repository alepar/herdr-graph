## How the clusters compose

- Seat-intent lifecycle across clusters 11, 12, 16 and 18. Every commit at head that retires a clone calls `threads::assignment::clear_restore_on_retire`: the observe cascade (src/observe/mutations.rs:252), `do_retire_seat` (src/plan/core_kinds.rs:424), `CloneRetire` (core_kinds.rs:1811) and the undo `displace` (src/undo/compensate.rs:494). `git grep` for `CloneLifecycle::Retired` assignments finds no other production retire site. The §14.6 "retire commit clears it" rule therefore holds across the whole tree. The other three intent transitions do not hold. `write_restore_intent` and `admit_threads_seat` have no non-test caller, so no production commit ever writes or advances an intent.
- Purge tombstones across clusters 8, 12, 16, 17 and 18. The tombstone predicate is honoured by `clone_status` (cluster 8), `do_resurrect_seat` (cluster 12), `holder_elsewhere` (cluster 16) and `compute_restore` (cluster 18). It is not honoured by `SeatResurrect::plan/mutate` or the teamspace-resurrect plan loop (cluster 12, reproduced by that reviewer), by `grammar::resolve_clone(Scope::Retired)`, by the undo candidate listing, or by `transcripts::export_rejections` (cluster 17). The clusters compose badly here. When one clone of a retired seat is purged, cluster 18's guard refuses the undo of the whole seat retirement, and its message names no remedy. The only remaining path back is `seat resurrect`. If the purged clone was the seat's only clone, cluster 12 showed that this path commits an Active seat with no clone. The guard and the resurrect defect therefore form one operator dead end. The cluster-12 fix closes it, and the undo refusal should then point to `seat resurrect`.
- Cluster 12 and cluster 16 disagree on the pre-D2 Finalize tombstone. Cluster 12 accepts it as Deferred OK, and cluster 16 lists it as a must-fix. Spec §8 says "A clone whose seat is already final (every seat before D2) is purged at once, with no intent". §14.2 is headed "Purge always writes a tombstone after D2". `purge_tombstone` writes `Finalize{seat}` for every seated clone with no D2 condition. Read literally, §14.2 does not supersede §8 before D2, so the shipped behaviour diverges from the spec's pre-D2 rule. In practice the effect is inert: no production path assigns a `threads_seat` at head (B1 below), so no purge can produce such a tombstone yet. Once hg-66u.7 lands and before hg-66u.31, the tombstones would build up. I carry cluster 16's item forward as written. It can be closed either by gating the tombstone on D2 or by an explicit spec amendment saying that pre-D2 tombstones drain once hg-66u.31's final-read acknowledgement exists.
- One-live-clone-per-seat (clusters 1, 16 and 18, plus the plan resurrect path). `check_free` runs only inside `ThreadsSeatMutation` Assign/Succeed. Undo (`compute_restore`/compensate) and resurrection reactivate a retired clone with its `threads_seat` and run no check, while spec §2 calls for writer-validator enforcement. This is unreachable at head because Assign has no producer. It becomes reachable as soon as hg-66u.7 wires the resolve-seat want, so it belongs to hg-66u.7 and hg-66u.29.
- Launch env and export detection (clusters 6, 7, 10, 13, 14 and 17). The interfaces agree. `config::Env.continuity_key` reads `HERDR_THREADS_CONTINUITY_KEY`, which equals `model::launch::ENV_CONTINUITY_KEY`. `report_args(hook, clone, pane, continuity_key, cwd)` is called positionally in the right order. The IPC key `continuity_key` matches the `#[serde(default)]` field on `ReportArgs`. `record_launch_env` stores `pane.0` and the variable names from the same `agent_env(&clone, false)` value passed to `StartAgent.env`. `check_export` compares that stored `pane` with the report's pane, which is the same id space that `clone_for_pane` already relies on. Before D1 the only recorded variable is `HERDR_GRAPH_CLONE`, which pane-creation env already supplies, so the detector is inert. That is consistent across the clusters, not a seam break.
- Writer inventory across clusters 12 and 19. hg-66u.35 added `cx.tree.delete_file(&loc.record_path)` in `ClonePurge::mutate` (src/plan/core_kinds.rs:1925; the base has no `put_file`/`delete_file` call in that file). `tests/instruction_writers.rs::instruction_source_writers_are_inventoried` scans production source for those calls, and its expected set lacks `src/plan/core_kinds.rs`. By static reading this confirms cluster 19's observed red test: the test fails at head only because the two clusters were merged together.
- Cross-incarnation id adoption across clusters 11 and 14. The observe matcher and `LiveIndex` now both accept a bound tab or workspace id in any incarnation, so they agree with each other and with spec §7. Together they also mean that if Herdr reissues a deleted workspace id after a restore (cluster 3's parked round-1 dissent), the matcher binds the teamspace to the reissued workspace and the reconciler then re-stamps the teamspace token onto it. Cluster 19's probe saw those `ReportWorkspaceMetadata` re-stamps after a handoff. No test and no guard covers the reissue case. Spec §7 accepts preservation as fact, and the dissent is parked "need human" in run.md, so I record it as untested scope, not a must-fix.
- herdr-threads pin across all clusters. The head gitlink is still cdc8423f (v2.6.4), and no commit in the range touches `third_party`, `Cargo.toml` or `Cargo.lock`. Spec §1 makes v3.0.0 (hg-66u.4, open and ungated) the bottleneck for ThreadsSeatView, SeatObservation and the resolve-seat want. Those are the producers that B1, B4 and B5 need.

## Assessment

The tree at head is an honest partial delivery. The ungated groundwork is in place and composes cleanly: the seat-intent data model and mutation, purge, the launch-env carrier and export detection, preserved-id tab/workspace matching, and Option D. The tree is red, though, because the writer inventory was never updated for purge. It also carries one shipped correctness defect, in seat resurrect over tombstones. And of the baseline, B1, B3, B4 (clones), B5, B7, B8, B9 and B10 are undelivered with no human scope-change row. B1, B4, B5, B7 and B8 are blocked only by open ungated beads, not by gates, so the gate exception in the Global Constraints does not excuse them.

## Seam walk (own view, before the ledger)

- SeatObservation and the step: a whole-read failure becomes `ThreadsRead::Unavailable` and changes nothing. A per-seat omission starts a refusal clock and becomes Unknown (never retired) after 90 s. Retired with an unacknowledged Restore leaves the clone alone. Resolved wins pane uniqueness. Unbound clones are removed from the baseline matches, so the diff does not report them closed. This matches spec §6 and §16.
- ThreadsSeatAssignment: Assign is write-once and checks for a single live holder. Succeed is admitted only against a matching Restore seat and epoch, with threads_done false, and is idempotent on replay. MarkLaunched is once per epoch. ClearOnReattach is epoch-gated. This matches §2 and §8.
- Keyed env delivery: the shell export is validated against `[A-Za-z0-9_.-]`, gets a leading space, and is sent via send_keys before agent.start. A bad value returns NeedsRevision. This matches §5.
- Resume driver: the restore trigger requires threads_done, an unlaunched epoch, a bare bound pane and a resumable session. The restart trigger requires a fresh Unresolved fact read after the incarnation change and fires once per incarnation. The ordinary start rule skips Restore and restart-covered clones. This matches §9, §16.7 and §16.8.
- hg-66u.80: `seated_clones` now requires a desired pane, so clones of a Dormant seat or teamspace are not inspected. `SeatActivate::mutate` writes a Restore intent for each seated active clone. Teamspaces become Dormant only by inactive create or by resurrect, and resurrect already writes intents, so no teamspace-activate path is missing.

- [Important][correctness, plausible] `SeatActivate::mutate` (src/plan/core_kinds.rs, hunk @@ -1176) writes the Restore intent but, unlike `do_resurrect_seat`, does not clear `occupant` or `runtime`. `plan_resume`'s restore launch requires `p.occupant.is_none()` (src/reconcile/planner.rs). `reattached_restore` clears the intent when the new seat reads Resolved and `c.occupant.is_some()` (src/threads/effects.rs). The diff's `occupancy()` ends occupancy only for matched clones in surviving panes, and a clone of a Dormant seat has no desired pane. Possible failure: an occupant that survives deactivation (for example the agent was killed with the tab and its SessionEnd hook never reported) would make reactivation clear the Restore with no launch, and the ordinary start rule also skips a clone with an occupant. The clone would then sit agentless with nothing surfaced in status. I did not verify whether the pane-closure or Absent path clears the occupant.
- [Minor][behavior-change] After hg-66u.80, `seat activate` of a seated clone with no resumable ended session (harness without resume, or no ended session on record) is recorded as `restore_stuck: not_launchable` instead of being started fresh as before this branch. This follows the spec's restore rule ("never launched fresh" before D1), but it extends that rule to a command the spec did not cover. The extension rests on an orchestrator decision in hg-66u.80, not a human row.
- [Minor][spec-provenance] The hg-66u.80 rule "reactivation is resurrection" was set by the orchestrator in an autonomous run after the task BLOCKED on a spec gap. It is recorded only as a post-implementation note, not as a spec section or a human decision.
- [Minor][design-consistency] `SeatActivate` writes the intent for every seated active clone even if the deactivation close never ran. In that case the seat reads Resolved or Unresolved and the restore-ack path sets threads_done without a command, so the intent is harmless. It does, however, route an otherwise ordinary reactivation through the resume driver.

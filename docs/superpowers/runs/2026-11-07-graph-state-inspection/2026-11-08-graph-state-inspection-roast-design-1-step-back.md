decision: redesign
triggers: shared-cause, defect-type
summary: Retarget the loaded-instructions record. Bind it to the native session it was injected into, and let only the hook write it. That replaces the timestamp ownership rule and the multi-writer last-writer-wins file, which together produce the Blocking finding and two Should-fix findings. The rest stays local and is swept in three clusters.
pattern: Three open findings come from one §2.3 / LoadedInstructions decision: the record is one last-writer-wins file per clone, fed by every path that renders instructions (hook, hook-codex, `seat --instructions`, `seat.resolve` for `seat --json`), and its tie to the current session is inferred from timestamps (`at` vs `occupant.since`). That inference fails on the real start order, where `seat --hook-prompt` runs before `session-report` (r1 [Blocking] §2.3 Status table, `unknown` row …). The tests can be written in the wrong order and still pass (r1 [Should-fix] §2.3 Status/unknown; hg-blw.11 …). Any non-hook writer can overwrite what the hook recorded (r1 [Should-fix] §2.3 "Who writes it" …). Separately, the JSON contract is incomplete in several places. That is one rule applied unevenly: text-only notices and states have no JSON field, though §2.1 says "The JSON is the contract".
clusters:
- json-contract: r1 [Should-fix] §2.2 JSON `"instructions":{"status","loaded_rev","loaded_at","source","truncated","stale_parts"}`; task hg-blw.4 acceptance, r1 [Should-fix] §2.4 Cost "scanned 5000 commits, older history not searched"; §2.4 Journal pointer to `ops`; §2.3 `@`-imports line; §2.5 tombstone footer, r1 [Should-fix] §2.2 With `--live`; Key abstractions Roster Errors "daemon down for `--live` is exit 5", r1 [Nit] §2.2 With --live "`live_pane_matches`: whether the snapshot still shows the committed binding"; §5 S1 unmanaged | rule: sweep every view (roster, roster --live, stack, log, sessions, ops). Any fact, notice or degraded state the text rendering shows must have a named, typed JSON field, and nullable values must be marked nullable. That covers loaded `parts` labels, `scan:{scanned,stopped_early}`, the tombstone count, `last_change` null plus a scanned-out marker, `live_unavailable` instead of an empty overlay, nullable `label`, and incarnation-aware matching via `same_server`. Notices that exist only in text go to the text rendering or stderr, never to stdout under `--json`.
- harness-discovery: r1 [Nit] §2.3 harness files "in the seat's cwd … and its ancestors: … `AGENTS.md`, `AGENTS.override.md`"; user-level `$CODEX_HOME/AGENTS.md`, r1 [Nit] §2.3 "`harness` one of `claude | codex` (the harness that reads that file name)" | rule: model each harness's documented discovery in one table, applied consistently. Codex walks from the Git root down to cwd, one file per directory, with the override winning, plus `$CODEX_HOME/AGENTS.override.md`. Claude reads AGENTS.md only when no CLAUDE.md exists. `harness` becomes a list, and a one-line caveat says that "present" does not mean "loaded".
- single-snapshot-reads: r1 [Nit] §2.1 "Each JSON document carries `schema: 1` and the `head` revision it was computed from"; Inventory "read once from HEAD"; HistoryWalker "walks `main` from HEAD", r1 [Nit] Key abstractions Inventory "Errors: `StoreError` only … maps to exit 6"; §2.2 Cost "one render per active seat" | rule: each invocation resolves HEAD to one CommitId and passes it to every component. A failure in one object (a seat render, a malformed history record) becomes a per-row error state or a skip with a warning, never a whole-command exit.
changes: The ownership and writer model of the loaded record, stated in §2.3 ("Who writes it", Status `unknown` row, record shape) and in Key abstractions LoadedInstructions (InjectionSource enum with SeatInstructions/SeatJson; "a record older than `since` is `Unknown`"; Lifecycle "last writer wins"), plus phase 2 in §3 and beads hg-blw.4 / hg-blw.11.
to: The record holds hook injections into one native session. It gains `native_session_id`. `seat --hook-prompt` (both harnesses) takes it from the hook's stdin payload (Claude, as `session-report` already does) or from the Herdr pane's agent session id, which resolve.rs already reads. Status is `current` or `stale` only when the record's `native_session_id` equals the clone occupant's native session id. A missing record, or one for another session, is `unknown`, with no comparison of `at` and `since`, so write order and the observer race stop mattering. A clone with no occupant yet shows the record as `pending`, or `unknown` with the session id shown. Only the hook sources write the record. `seat --instructions` and `seat --json` stop writing, so InjectionSource shrinks to `Hook | HookCodex`. hg-blw.11 drives the real hook chain from a clone with no occupant and asserts that the result reaches `current`.
dissolves: [Blocking] §2.3 Status table, `unknown` row; Key abstractions LoadedInstructions "a record older than `since` is `Unknown`", [Should-fix] §2.3 "Who writes it" (`seat --instructions`; daemon `seat.resolve` for `seat --json`); LoadedInstructions Lifecycle "last writer wins", [Should-fix] §2.3 Status/unknown; hg-blw.11 second acceptance and hg-blw.4 status tests
remains: [Should-fix] §2.3 record `parts`/`omitted`/`cut`; Status `current` "every part at HEAD has the same label and digest as the record", [Nit] Key abstractions Scope "resolves retired targets too … reuses `instruction_source`'s `pick` logic and error wording"; hg-blw.7 acceptance, [Nit] §2.3 Digest choice ("their `path` is `seat.toml` or `template.toml`"); Status `stale` row "one `git log -1` per changed path", [Nit] Key abstractions Inventory "Errors: `StoreError` only … maps to exit 6"; §2.2 Cost "one render per active seat", [Nit] §2.3 harness files "in the seat's cwd … and its ancestors: … `AGENTS.md`, `AGENTS.override.md`"; user-level `$CODEX_HOME/AGENTS.md`, [Nit] §2.3 "`harness` one of `claude | codex` (the harness that reads that file name)", [Should-fix] §2.2 JSON `"instructions":{"status","loaded_rev","loaded_at","source","truncated","stale_parts"}`; task hg-blw.4 acceptance, [Nit] §2.1 "Each JSON document carries `schema: 1` and the `head` revision it was computed from"; Inventory "read once from HEAD"; HistoryWalker "walks `main` from HEAD", [Should-fix] §2.4 "What it reads per commit: … the `ActionRecord`, when present"; JSON row `action:{id,kind,undoable,undone}`; sample "act_01… undone", [Should-fix] §2.4 Cost "scanned 5000 commits, older history not searched"; §2.4 Journal pointer to `ops`; §2.3 `@`-imports line; §2.5 tombstone footer, [Should-fix] §2.4 Scope membership "A commit is in scope when any of these holds: … `--by <seat>`"; LogQuery "or (with `--by`) when the requester's seat matches", [Should-fix] §2.2 With `--live`; Key abstractions Roster Errors "daemon down for `--live` is exit 5", [Nit] §2.2 With --live "`live_pane_matches`: whether the snapshot still shows the committed binding"; §5 S1 unmanaged
scope: inside — the goal clause "which instruction files each seat's agent was handed and whether they are stale (`instructions stack` plus the loaded record)" and the §3 rejection "Commit the loaded revision onto `CloneRecord`" both stand. The record stays local in `.graph-local/`, daemon-free and best-effort. Only its key and its writer set change. B5 "Staleness is shown, not notified" is untouched.
recommendation: Patching the timestamp rule (reordering the Claude hook chain, adding a grace window, adding a writer precedence) leaves the Codex observer race and the multi-writer overwrite as separate holes that the next round will find again. Binding the record to the session id and keeping it hook-only removes all three findings in one decision, at about the cost of a single local fix. The rest are independent or rule-level, and the three sweeps above handle them.

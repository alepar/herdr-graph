## Resolver against spec 4.6 and the model::manager key abstraction

- Precedence in `Pointers::effective_manager`:
  - The live node manager gets None.
  - Otherwise an explicit `manager` wins. It is integrity if that seat is missing.
  - Next comes the teamspace `default_manager`, unless it is the seat itself. It is integrity if that seat is missing, with the teamspace as holder.
  - The last fallback is `live_node_manager()`.
  - This matches the spec rule exactly.
- A `node_manager_seat` that is missing or retired counts as unassigned (None), not as integrity, as 4.6 and 4.10 require.
- A retired seat is still returned by `effective_manager`. `ancestors` then walks through it using that seat's own effective manager, and `manager_chain` filters retired seats out. This gives the "transparent" semantics, so a stale pointer to a retired seat never raises integrity.
- `ancestors` uses a visited set. A cycle becomes `unresolved(seat, "manager", n).because("forms a manager cycle: a -> b -> a")`, so cycles and unresolvable pointers both go through the single Part A `unresolved` constructor (B4 / 4.2).
- `nearest_surviving_manager` returns the first ancestor that is neither retired nor in the retiring set. That is the 4.11 "nearest surviving ancestor" rule. Callers in plan::managers::reparent handle the integrity fallback (seam).
- `cycle_from` / `would_create_cycle` replay `PointerEdit`s on an in-memory `Pointers` and report the first loop reachable from the subjects. A missing-target pointer ends the walk silently, which is documented. The make_plan cycle guard (plan/managers/cycle_guard.rs, another cluster) uses `Pointers::apply` for create, manager, default and node-manager edits. For `seat.resurrect` it un-retires the seat directly and keeps its stored `manager`. I opened that file only to check the named risk below.
- The module writes no records, builds no plan effects, renders nothing and knows nothing about IPC. That respects the "Must not" list. It also exposes `live_node_manager(tree)` as the single "who is the node manager" answer.

## Concerns

- `PointerEdit::Live` always resets `manager` to None, which is right for a newly created seat but wrong if anyone uses it for resurrection. cycle_guard correctly avoids it for `seat.resurrect` by mutating the `pub` `seats` map directly. Because there is no `Resurrect` variant, the replay rule for that effect lives outside model::manager and depends on public field access. A future caller that reaches for `Live` would silently drop the stored pointer and could miss a cycle.
- The cycle error always reports field `manager`, with holder = the walk's starting seat and target = the revisited seat. When the closing edge is a teamspace `default_manager`, holder/field/target do not identify the offending pointer. The `because` text carries the full walk, so the error can still be diagnosed. This is cosmetic.
- Each free function (`effective_manager`, `manager_chain`, `live_node_manager`, `nearest_surviving_manager`) calls `Pointers::load`, which reads every seat (archived included), every teamspace and graph.toml. That is fine per call. A future caller that loops over seats with the free functions instead of one `Pointers` would do quadratic reads.
- `referenced_seat_template` integrity errors use the default reason "not found at the committed revision" even when called on a plan-time overlay tree (templates/kinds.rs, seat_definitions.rs), where the tree is not the committed revision. Only the wording is affected.

## Analysis

What landed matches the parts of §4.5 it covers:

- Step 1 failure branch keyed on exit code: 5 (show the line, carry on without seat rules, re-run `/seat` later, do not repair the daemon unless instructed), 6 (do not retry, report to the node manager the line names or to the user, carry on), other (show the line, do not guess). This delivers B2/B3 at the skill level ("carry on doing what they can"). The texts agree with what the CLI actually prints: `SEAT_UNAVAILABLE` / `SEAT_INTEGRITY` in `src/cli/seat.rs`, and the three suffix forms from `node_manager_suffix` ("report it to the node manager seat <name> (<st>)", "no node manager is assigned; report it to the user", "you are the node manager seat; report it to the user"), all of which the skill's "or to the user when the line says so" handles. `HOOK_PROMPT` ends with "If /seat fails, follow the skill's failure step.", so the hook points at this branch. Exit 2 (not in a Herdr pane, no instance) falls to "any other failure", which is right.
- Step 3 names `manager` and `node_manager` as escalation targets for lifecycle issues and lists the three categories from the human request (environment, peer conflicts, own ability to operate). The reply really carries both fields (`seat_reply`, lines 317-345 at head), so the escalation path for an ordinary seat is reachable from the production `/seat` entry point (B5).
- Install path unchanged: the skill is embedded by `include_str!` in `setup_claude.rs`, so `setup claude` ships the new text with no further wiring.

What has not landed in this cluster at head:

- §4.12 requires that when `reports` is non-empty "the skill tells the session it is a manager: listen for, detect and unblock its reports' lifecycle issues", and that when the session's own seat is the node manager "the reply and skill say so and carry the node-manager duties (shared text with `templates/node-manager/AGENTS.md`)". The skill has neither. That work is planned as hg-k4l.19 (blocked on hg-k4l.14, the node-manager template), and both beads are still open. The reply also has no `reports` field yet (`seat_reply` emits only `manager` and `node_manager`), and `templates/node-manager/` does not exist at head. The human request in the baseline says "managers are tasked with listening, detecting, unblocking". At head, nothing reachable from `/seat` tells a manager seat about that duty. The skill half of this gap belongs to this cluster; the reply-field half (`reports` in `src/bootstrap/mod.rs`) and the template half (B10 default templates, hg-k4l.14) leave the cluster and are for the seam reviewer to trace.
- The node manager's own `/seat` gives bad routing. A node manager has no parent, so `manager_chain` is empty and `manager` is null, while `node_manager` is the session's own seat. Step 3 then says "when it is null, go to the `node_manager`", so the node manager is told to escalate to itself. The CLI's integrity suffix already handles this case ("you are the node manager seat; report it to the user"), but the skill's step 3 does not. Intended fix: hg-k4l.19's node-manager branch.
- No test pins the new skill text. `seat_skill_has_instruction_steps` checks only the Codex line, "Follow `instructions.text`" and the `data` line. The failure branch and escalation paragraph could be dropped or reworded out of step with `SEAT_UNAVAILABLE` / `SEAT_INTEGRITY` with no failing test. The install tests compare the installed copy against `include_str!`, so they cannot detect content regressions.

Minor, acceptable as is:

- Step 3 names the targets but not how to reach them. The reply's `threads_seat` field is the obvious address and the skill does not mention it. The human said "how they communicate is open", so this is not required.
- The exit-5 CLI line says "get the graph daemon fixed (ask your manager or coordinator)" while the skill says "do not try to repair the daemon unless you are instructed to". They do not conflict, since asking is not repairing. On exit 5 the session has no seat context, so it cannot learn its manager from the reply anyway.

## Verdict
not ready (seat skill lacks the manager and node-manager duty text from spec §4.12 / human request; hg-k4l.19 and hg-k4l.14 still open; node manager is told to escalate to itself)

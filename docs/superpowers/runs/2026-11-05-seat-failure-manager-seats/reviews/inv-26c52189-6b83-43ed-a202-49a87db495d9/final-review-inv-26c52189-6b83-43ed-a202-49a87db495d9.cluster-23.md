## Findings

- tests/e2e_private_herdr.rs (tier 3, not touched by this diff) still expects closure retirement of a rig's first seat. Under the new behaviour that seat becomes the node manager and is exempt.
  - E2e::start runs plain `init` with no node-manager opt-out. `create_teamspace_with_seat` then creates "foreman" as the graph's first seat, so SeatCreate assigns it node_manager_seat. src/observe/classify.rs (node_manager_gone, lines 279-331) and CascadeMutation (src/observe/mutations.rs:314) exclude the node manager from tab/workspace cascades.
  - Affected tests: e2e_close_tab_retires_seat_and_clones (line 780) waits for foreman to be "retired". e2e_close_workspace_retires_all_incl_dormant asserts the teamspace retires and "nothing is recreated". close_tab_and_wait (line 866) is used by e2e_undo_tab_close_restores_in_new_tab and the undo-adoption test at line 1062. These should time out or fail their assertions.
  - The tier-2 twins of the same flow in daemon_composed needed exactly this opt-out to pass. This is static analysis; tier 3 was not run.
  - Plan Task 22 lists e2e_private_herdr.rs as a file to fix and says tier 3 should run where available.
- The end-to-end integration sweep the spec and plan require has not landed. hg-k4l.22 is open, and tests/manager_seats_sweep.rs does not exist at head. The missing flows are:
  - `/seat` exit 6 through the real binary with stderr naming the node manager (B4, §4.3).
  - `init --with-examples` + `application apply office` yielding the node manager (B10).
  - manager set, who/show chains (B9), retire-middle-manager reparent (B6) and its undo, and node-manager set move rewrites (B13).
  - Refusal of node-manager retirement and placement changes (B8/B11).
  - node-manager set clearing the warning via the daemon (B12).
  - Each piece has unit coverage in other clusters. None is exercised from a CLI or daemon entry point in tests/. §4.14 puts "CLI behaviour (exit codes 2/5/6, warning line) in tests/ with TestRoot", and exit 6 has no tests/ coverage.
- Six composed fixtures call `support::node_manager_opt_out`, which puts the graph into a dangling-node-manager state. Production code treats that state as a fault: the CLI warns about it (node_manager_warning::check), and bootstrap emits the "no node manager is assigned; report it to the user" integrity suffix. The tests still pass, but they now run outside any state a real graph reaches through plans. Plan Task 22 step 1 prescribes the opposite fix: give the rig a dedicated first seat, such as `seat create nm --active` or `application apply office`, so the old flow's seats are ordinary. The opt-out also means no composed tier-2 test runs retirement, undo or tab-close with a live node manager present, which is the production default.
- daemon_composed ORG_KINDS (length 24) adds "node_manager_set" but not "manager_edit", so every_kind_and_command_registered does not guard ManagerEdit's mutation registration. integration_sweep's sweep_every_request_kind_has_a_mutation does cover ManagerEdit, so there is no actual hole. The two lists simply disagree.
- node_manager_warning `unassigned_graph_with_a_seat_warns_once_and_assignment_silences_it` asserts `stdout(&before).contains("s")`. That matches almost any output, so it does not show the seat was listed. Matching the seat id or a name column would.
- tests/daemon_error_commands.rs Fixture binds a listener on root.herdr_socket() and spawns an accept thread, but every run overrides HERDR_SOCKET_PATH to dead.sock. The listener is never contacted. It is dead fixture code copied from seat_exit_codes, where it is equally unused.

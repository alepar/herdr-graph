## What the cluster changes

- `pointer_restores` (preview.rs) reads the `reparented` compensation rows of the action being undone and, for each row whose holder still exists and still holds `new`, emits a `seat.manager` / `teamspace.default_manager` effect `new -> old`; other rows become plan warnings ("changed since the retirement", "no longer exists", "unreadable").
- `restore_preview` appends those effects and warnings to the undo plan of `ClosureCascade`, `Retire` and `ApplicationRetire` actions.
- `restore_mutate` (compensate.rs) recomputes `pointer_restores` after the seats are resurrected and writes them through `plan::managers::apply_pointer_effects`, so all pointer writes stay inside plan::managers (key-abstraction rule) and inside the undo plan (B7).
- Tests: fixture opts out of first-seat assignment and registers the test pointer mutations; new tests cover the node-manager creating-hydrate undo guard (B8, §4.9), reparent recording on ApplicationRetire and on undo-of-hydrate (§4.11 undo-driven route), pointer restore on undo of `seat retire` (seat and teamspace default) and of `application retire`, and the changed-pointer warning path.

## Reproduction

In a review-owned detached worktree at head (since removed), a test was added: seats nm (node manager, alpha), x (alpha), a and b (teamspace beta); pointers b->nm, a->b, x->a; `teamspace retire beta`; then undo.

- The Retire action recorded rows in retirement order: `[x manager old=a new=b]`, then `[x manager old=b new=nm]` (`reparent` rewrites x again when b retires, as its doc comment says).
- The undo plan carried the warning "manager pointer of x changed since the retirement (now nm); left unchanged" for row 1, and an effect for row 2 (`x: nm -> b`).
- After apply, x.manager == b; the pre-retirement value was a. Assertion `x.manager == Some(a)` failed.
- The 37 existing `undo::` tests passed at head.

Cause: `pointer_restores` checks every row against the current pointer value and processes rows in forward order. Rows that rewrite the same holder more than once in one action must be unwound in reverse order with the expected value updated after each step (or collapsed per holder to first `old` / last `new`), otherwise only the last hop is undone and the earlier hop is misreported as an external change. The same applies to `default_manager` rows of a teamspace whose default was a seat that retired before its own manager in the same action (`teamspace retire`, `application retire`, observed closure cascades).

## Findings

- Undo of a multi-seat retirement restores the wrong manager pointer when a holder was rewritten twice in the same action (src/undo/preview.rs `pointer_restores`): reproduced with `teamspace retire beta` over chain x->a->b->nm, undo leaves x->b instead of x->a and emits a false "changed since the retirement" warning; violates §4.11 "restores each pointer the reparent rewrote" and B6 restore semantics.
- The undo action record does not list the pointer restores among its changed objects (restore_mutate writes them through `apply_pointer_effects` without `acc.changed`), so `ops`/action history of the undo omits them; minor surfacing gap, not a correctness failure.

## Must fix before landing

- Fix `pointer_restores` (src/undo/preview.rs) to unwind `reparented` rows per holder in reverse order (or collapse each holder's rows to first `old` and last `new`) so undo of a teamspace/application/cascade retirement that retires a manager chain restores the original pointer; reproduced: x->a->b->nm, `teamspace retire beta`, undo leaves x.manager = b and warns falsely (B6, spec §4.11); add a regression test for that chain.

## Untested scope

- Undo of any retirement that rewrites the same holder more than once (chained seats in one teamspace or application retire, closure cascade) has no test; the reproduction above fails.
- No test for the "no longer exists" and "unreadable" warning branches of `pointer_restores`.
- No test for restoring a `teamspace.default_manager` pointer that changed after the retirement (only the seat-manager changed branch is tested).
- No test for undo of a `ClosureCascade` action restoring reparented pointers.

## Deferred OK

- Pointer restores are not added to the undo action's changed-object list; history surfacing only, undo of an undo is not supported, so no compensation depends on it.
- Retired holders (archived seat records) count as existing in `pointer_restores`, so a holder retired later by another action can get its archived pointer restored; harmless to live state.

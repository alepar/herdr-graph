## Analysis

instructions.rs: `template_participation` now resolves the template_ref template, each application and each application's template with `?` instead of `let-else continue`, and `push_member` builds the shared-seat-template error with the member id as holder. `seat_parts` uses `unresolved(seat, "record", seat)`, so its text repeats the id ("st_x: record st_x not found ..."), which is legible. One dangling reference is still dropped silently: a `template_ref.member` that names no member of the template (`record.members.iter().find(..)` returns None, so the member's AGENTS.md and its shared seat template are skipped). This is the pre-existing behaviour. H3 did not list it among the silent drops (C33 limits B4's scope to those three), and only out-of-band edits can produce it.

Other callers of the changed functions: `doctor` now reports an integrity error as "seat X: cannot render instructions: ...", an improvement. `cli::seat` hook rendering uses `.ok()`, so a broken seat gets no injected instructions and `/seat` then fails with exit 6, as B4 intends. src/templates/kinds.rs:1457 (TemplateEdit cap warnings) walks `template_participation` over every live seat with `?`, so one damaged, unrelated seat now fails any template edit with a store error. H3 accepted this blast radius for damaged graphs only. It is noted as deferred.

mod.rs: the `fail` closure computes the suffix only for integrity errors and is reused across bound_paths, Pointers::load, manager_chain, seat_ref and render_instructions, so every route is classified the same way. `Pointers::load` and `seat_ref`'s `all_clones` read every seat and clone, archived ones included, on each bound `/seat`. A malformed unrelated record therefore turns every `/seat` into an internal failure (exit 1) where it used to succeed. That is the plain-read classification the spec requires, but it widens the read set; it is noted as deferred. The remaining `if let Some` skip for `paths.applications` in bound_paths cannot be reached for a missing application, because `template_participation` fails on it first.

show.rs: the line is appended only on the id/name route. A seat record reached through `show <path>` (show_path) prints without the manager line. Spec 4.12 says "show <seat>", so this is a gap at the edge of the spec, not a defect.

tests.rs: `fx()` now opts fixtures out of first-seat assignment, and new helpers write records directly through test-only bookkeeping mutations (TestManager, put_path). Those helpers stay in the test module and register only in the test fixture registry.

## Scope of the cluster

The slice adds `StoreError::Integrity { holder, field, target, reason }`, the single constructor `unresolved(holder, field, target)` with the default reason "not found at the committed revision", and the modifier `StoreError::because(reason)`, which replaces the reason on `Integrity` and is the identity on every other variant. It also adds two unit tests covering the constructor, the Display text, and the reason swap, including the identity on a non-Integrity variant.

## Spec conformance

- Design §4.2 asks for one store-level variant shaped as `StoreError::Integrity { holder, field, target, reason }`, produced by one `unresolved(holder, field, target)` helper, with `referenced_seat_template`'s missing, wrong-kind and team-structure failures mapped to it. The variant and helper match that shape exactly. `because` is how the wrong-kind and team-structure reasons are carried (src/model/effective.rs:129-136), along with the manager-cycle reason (src/model/manager.rs:164-165). The variant stays a single integrity classification, so this helper does not widen it.
- "Build only via `unresolved`" holds at head. Every other textual occurrence of `StoreError::Integrity {` in src/ is a pattern match or test destructuring (src/model/manager.rs:312, src/bootstrap/mod.rs:218/332, src/writer/mod.rs:95, src/daemon/registry.rs:70, src/cli/daemon_error.rs:123, src/plan/managers/reparent.rs:72). None of them construct the variant.
- The Display text `{holder}: {field} {target} {reason}` names the holder, field and target, as §4.3 requires. The HEAD revision and node-manager suffix are appended downstream in `resolve_error` (src/bootstrap/mod.rs), which belongs to the seam and bootstrap clusters, not this one.
- Plain read failures (`Io`, `Corrupt`, `Git`, `UnknownCommit`, `InvalidPath`, `NoInstance`) are untouched and remain distinct variants. The downstream classifiers (`CommandError::from_store`, `Fail::from`) map only `Integrity` to the non-transient outcome, which preserves §4.2's split between integrity and I/O or parse failures.

## Code quality

- `because` is a small, total, tested modifier, and it keeps reason text out of call sites that would otherwise rebuild the variant by hand. The earlier task review recorded it as a minor deferral ("extra-helper"). It is consistent with the "one constructor" rule because it can only transform an existing `Integrity`, never create one.
- The `#[error]` format has no separator before `reason`, so callers have to phrase reasons as predicates ("is not a seat template", "forms a manager cycle: ..."). Every call site at head does this, so the rendered text reads correctly.
- No serde derive was added to `StoreError` and no IPC type changed. The variant never crosses the wire as a structured value, only as `CommandError` text, so the no-IPC_VERSION-bump constraint is unaffected.
- I did not run tests for this review. A cargo run in the caller checkout would write its `target/`, and a review-owned worktree would need a multi-gigabyte build copy for an 84-line change. The two unit tests are straightforward and match the code by inspection. digest.md records the task-level test runs.

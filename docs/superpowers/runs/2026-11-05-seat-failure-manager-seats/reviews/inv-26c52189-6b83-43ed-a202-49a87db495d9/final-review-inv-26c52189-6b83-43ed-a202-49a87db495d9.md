Exit 6 has no binary-level test.

## Seam analysis

- Move-then-close strands the node manager (B11). This only shows up when the observe, reconcile and plan-guard clusters run together, and no cluster reviewer owned it; cluster 16 left it to the seam. Trace at head:
  - The node manager's pane is dragged to another tab. src/observe/classify.rs (tab_gone with survivors > 0) puts the seat in `moved_out`. src/observe/mutations.rs:595 sets `rec.moved_out = true`, and the warning says its placement "is not reverted".
  - The pane is then closed. The classify `pane_gone` branch for the node manager pushes the clone to `gone` (availability Absent) and retires nothing. That is correct for B8.
  - src/reconcile/planner.rs:610 then skips CreateTab for any `tab.moved_out` seat, and :526 skips CreateWorkspace for it.
  - No production path ever clears `moved_out`. The only writers are the observed move (true), new-record constructors (false) and `admit_runtime`, which only tests call.
  - The `make_plan` guard refuses deactivating, retiring or re-placing the node manager.
  - Result: the node manager stays Active with no pane anywhere, permanently. The only way out is moving the role away with `node-manager set`.
  - The human said "gets reopened if it ever is closed". Spec §4.9 tolerates moves, but promises reopening for closure, and this is a closure. Reachable from a normal Herdr pane drag followed by a pane close.
- Skill and reply disagree for the node manager. bootstrap gives the node manager `manager = null` and `node_manager = self`. Skill step 3 says "when it is null, go to the node_manager", so the node manager is told to escalate to itself. The CLI integrity suffix handles this case ("you are the node manager seat; report it to the user"); the skill does not.
- Undo does not compose with reparent records. `plan::managers::reparent` writes one row per hop for the same holder within one action. `undo::preview::pointer_restores` judges each row on its own against the current value, in forward order. Each cluster is right in isolation, and the pair is wrong.
- Test fixtures hide production state. Lib fixtures (`plan::managers::testing::opt_out`, cfg(test)) and six composed fixtures (`support::node_manager_opt_out`) commit a dangling `node_manager_seat`. Production code treats that state as a fault: the CLI warns about it and seat.resolve tells the seat to report to the user. So no tier-2 test runs retirement, undo or tab-close with a live node manager, which is the production default. Tier-3 tests/e2e_private_herdr.rs has no opt-out, and its first seat ("foreman") now becomes the node manager. Its closure-retirement assertions should fail (cluster 23, static).
- The pieces that do compose cleanly:
  - `live_node_manager` is the single answer used by the warning, bootstrap, reconcile/observe and the plan guard.
  - `from_store` is the single store-error classifier used by the daemon `seat.resolve` and `who`.
  - `daemon_error::classify` is the single CLI mapper, and it has no wildcard.
  - The `graph_sha` precondition rejects concurrent first-seat or node-manager-set plans as stale.
  - The CascadeMutation apply-time recheck keeps B8 through a concurrent role move.
- Every recorded test run covers a partial suite at d2c7509, before hg-k4l.17 merged. No full `cargo test` run of 90e9118 exists, and none of the reviewers could link a build on this host.

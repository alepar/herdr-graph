## Exit-code table check (spec §4.4)

- `classify` is an exhaustive `match` over every ClientError variant and every IpcErrorCode, with no wildcard arm. A new IPC code will therefore fail to compile until it is classified, which is the property the key-abstraction digest asks for.
- The not-in-Herdr guard applies only to no-reply conditions (Unavailable, Frame, NoInstance). A real Remote reply keeps its own row, and a unit test checks that Integrity outside Herdr stays exit 6. This matches the table's first row.
- `strip_dot` stops the double period when a daemon message already ends in "." (for example the still-starting message), and a test covers it.
- Command-specific arms stay in the commands, as the spec requires: StillRunning in request `mutate`, and `report_apply` in plan. That behaviour is unchanged from before the diff.
- `session-report` and `doctor` are documented exemptions in the daemon_error module header. session-report is a hook path that spools on failure, which is consistent with "must never fail".

## Findings

- Stale exemption in the regression guard: `AWAITING_HG_K4L_3 = ["who.rs", "ops.rs", "request.rs", "undo.rs"]` in src/cli/daemon_error.rs:282 is still present at head. Its own comment says to drop the entries once hg-k4l.3 routes those files through daemon_error, and that is now done. As a result `no_command_matches_unavailable_itself` skips exactly the four files B14 changed. If someone reintroduces a `ClientError::Unavailable` fallback or a `.map_err(remote)` in who/ops/request/undo, this test will not catch it; only the binary test in tests/daemon_free_reads.rs would, and only for the forms it lists. I checked statically that none of the four files contains `ClientError::Unavailable`, `.map_err(remote)` or `fn remote(` at head, so emptying the list would pass.
- `session-report --from-hook claude` is not on the warning's exempt list. The installed Claude SessionStart hook runs `seat --hook-prompt; session-report --from-hook claude`, so on an unassigned graph every session start prints the warning line on the hook's stderr and also loads every seat and teamspace record from git. §4.10's exemption list does not name session-report, so this matches the letter of the spec. Exit is still 0, and Claude Code does not show hook stderr to the model on success, so the effect is noise and added hook latency rather than a failure.

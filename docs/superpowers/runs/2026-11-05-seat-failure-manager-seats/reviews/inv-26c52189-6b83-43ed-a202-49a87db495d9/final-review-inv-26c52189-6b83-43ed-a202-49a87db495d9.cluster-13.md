## Analysis

classify. The three containment loops stay disjoint. A node manager tab or pane inside a closed workspace is absorbed by the workspace branch (`absorbed_seats` / `ws_gone` checks), so nothing is ended twice. `node_manager_gone` runs after the loop that ends occupancy for intent-explained `gone` entries, so the two sources do not overlap. A teamspace id in `gone` was already supported, because intent-explained workspace closures emitted one before this change. The workspace cascade's `retire` list no longer starts with the teamspace when the node manager's teamspace is involved. `CascadeMutation` sorts ids by kind, not position, so the "root first" doc comment on `Cascade.retire` is no longer strictly true, but no consumer depends on it.

mutations. The apply-time re-check is correct with reparenting. `reparent` computes the retiring set per seat from the overlay, so a skipped node manager stays a surviving manager, and reports of other retiring seats resolve to it. `live_node_manager` fails only on layout read errors, never on a dangling `node_manager_seat` (that yields None), so the new `?` in `CascadeMutation::apply` cannot turn a pointer integrity problem into an aborted cascade. That keeps spec 4.11's "never aborts the cascade".

Apply-time race: classification runs before a concurrent `node-manager set`, and the apply runs after it. The skip leaves the node manager's seat, clone and teamspace records untouched. Runtime stays Present/bound and the occupant is not ended, while the cascade op's precomputed `ends` still emit SessionEnded. Reopening still follows, because the planner keys on live snapshot ids, and B8/B11 hold. Only the bookkeeping is stale, and no test settles through this path. The reverse race (classify while the seat is node manager, apply after the role moved) leaves the old node manager Active and absent, so it is reopened rather than retired. That is conservative and acceptable.

The move warning is computed once per classification. It can repeat if a step's ops fail and the next diff re-derives the same move element; the extra lines are cosmetic.

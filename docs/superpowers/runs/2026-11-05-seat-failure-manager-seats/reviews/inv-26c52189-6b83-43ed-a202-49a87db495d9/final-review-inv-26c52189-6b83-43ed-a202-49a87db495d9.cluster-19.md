## Scope and what changed

- `WhoReply` gains `manager_chain: Vec<NamedId>` with `#[serde(default)]`, so a new CLI parses an old daemon's reply. A new daemon talking to an old CLI also works, because `WhoReply` does not set `deny_unknown_fields`.
- `manager_line(chain)` renders `manager: a (st_a) -> b (st_b)`, or `manager: none assigned` when the chain is empty.
- `named_manager_chain(tree, seat)` loads `model::manager::Pointers` once and maps `Pointers::manager_chain` to named ids. It never reads `manager`, `default_manager` or `node_manager_seat` directly, which matches the model::manager key abstraction. `show` (src/bootstrap/show.rs:158) reuses it, so `who` and `show` print the same line.
- `WhoReply::render` adds the manager line after the identity path. An unbound reply stays the single line `unbound`.
- The `who` IPC handler now maps store errors through `CommandError::from_store` instead of `CommandError::internal`, so a `StoreError::Integrity` from the chain walk becomes `IpcErrorCode::Integrity` (exit 6 at the CLI through cli::daemon_error).

## Correctness notes

- `Pointers::manager_chain` lists only live seats and walks through retired ones. Every id it returns is a key of `Pointers::seats`, so the `ok_or_else(unresolved(..))` in `named_manager_chain` cannot fire. It is a harmless guard, not a defect.
- A chain integrity error fails the whole `who` reply, so the caller loses its identity line as well as the chain. This matches §4.12/§4.4, where the integrity failure is the escalation signal (exit 6 naming the node manager), so I am not raising it as a defect.
- `who()` now loads seats twice: once in `Graph::load` and once in `Pointers::load`. That is an efficiency cost on a per-call read, not a correctness issue.
- No in-tree consumer parses `who` text output as a single line (checked src, skills, templates, README). The only renderer is src/cli/who.rs, which prints the text, so the switch to two lines breaks nothing in this repository.
- Test fixture: `fx()` now calls `plan::managers::testing::opt_out`, which commits a `node_manager_seat` naming a seat that does not exist. First-seat assignment therefore does not fire, and the earlier `who` tests keep their meaning (`manager: none assigned`). The manager-chain tests set pointers through a test-only bookkeeping mutation (`test_seat_manager`) that writes records inside a mutation, which keeps to the all-mutations-via-mutation rule in test scope.

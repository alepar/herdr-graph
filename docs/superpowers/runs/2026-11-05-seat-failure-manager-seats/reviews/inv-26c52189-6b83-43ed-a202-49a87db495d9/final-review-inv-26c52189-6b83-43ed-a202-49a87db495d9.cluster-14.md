## What the cluster changes

- `plan::managers` is a new module. It holds the pointer-effect constructors (`seat.manager`, `teamspace.default_manager`, `graph.node_manager_seat` with `graph_sha`), the overlay writers `set_seat_manager`, `set_default_manager`, `set_node_manager` and `write_graph`, the `graph.toml` blob precondition (`graph_blob`, `graph_relied_on`) and `apply_pointer_effects`.
- `make_plan` (src/plan/kind.rs) now calls `managers::admit` on every plan's effects. `admit` runs `retire::refuse_node_manager_retirement` and then `cycle_guard::refuse_cyclic_chains`. `plan/apply.rs:139` calls `make_plan` again before apply, so both guards also run at apply time, on the replan and on undo.
- `ManagerEdit` (`plan manager set|clear <seat|teamspace> [<manager>]`) checks four things: the manager is live, the subject is not the live node manager, the edit is not a no-op, and no member chain becomes a cycle. It relies on the subject's rev, the manager's rev and the graph blob. `mutate` validates again and applies the listed effects.
- `NodeManagerSet` (`plan node-manager set <seat>`) assigns the role, or moves it. A move rewrites every live seat whose `manager` is the old holder, and every non-retired teamspace whose `default_manager` is the old holder. The live old holder then reports to the new one, and the new holder's own `manager` is cleared. A dormant target is activated through `SeatActivate` as listed effects. An active seat in a non-active teamspace is refused. A missing or retired recorded node manager is handled as an assign.
- `first_seat`: `qualifies`, `assignment`, `apply_assignment` and `forces_active`. `SeatCreate` is the only caller (src/plan/core_kinds.rs:996, 1063, 1084). The first seat is forced Active, and a dormant teamspace is activated as an induced effect.
- `reparent` (apply side) runs inside `do_retire_seat` before archiving. It records `{holder, field, old, new}` rows under the `reparented` compensation key. A lenient mode, used for observed cascades, falls back to `live_node_manager` and records a note.
- `reparent_effects` (preview) is listed by SeatRetire, TeamspaceRetire and CloneRetire (last clone).

## Defect analysis

- `reparent` (src/plan/managers/reparent.rs) calls `nearest_surviving_manager(seat, ..)` unconditionally, before it checks whether the retiring seat has any reports. `reparent_effects` only resolves a chain when a report exists. Consider a planned retirement of a seat with no reports whose own chain is broken: a dangling explicit `manager`, or a cycle above it. The plan and the apply-time recompute both pass, then `do_retire_seat` fails at apply with `StoreError::Integrity` (Fail::Data). A broken chain can only come from an out-of-band edit, because `layout::all_seats` and `list_teamspaces` include archived records and retired managers are transparent. The failure is clean, but it surfaces at apply time instead of plan time. Returning early when there are no seat or teamspace holders would fix it.
- `refuse_node_manager_retirement` calls `live_node_manager`, and so `Pointers::load` over every seat and teamspace, on every plan, including plans with no seat effects. An unreadable seat record anywhere now fails unrelated plans, such as instructions edits, with a store error. It also adds a full scan to each plan. This is minor and acceptable for now.
- `covers_all_clones` judges `clone.retire` and `runtime.close_pane` separately. A plan that retires one node-manager clone and closes the pane of the other would pass. No kind emits that combination today.
- The NodeManagerSet plan and ManagerEdit are correct against concurrent change. `node_manager_effect` carries `graph_sha`, so a recompute against a changed graph.toml differs and the apply is rejected as `stale_plan`. ManagerEdit validates again in `mutate`. Two concurrent first-seat `seat create` plans resolve the same way: the second recompute drops the assignment effect and is rejected.

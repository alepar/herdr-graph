## How the clusters compose

Composition defect A comes from first-seat assignment (hg-k4l.23) combined with the node-manager guards (hg-k4l.8 make_plan refusal and hg-k4l.9 closure exemption).
- `first_seat::assignment` makes the first seat created by SeatCreate the node manager.
- `refuse_node_manager_retirement` then refuses its retire, deactivate and close.
- `observe::classify` routes its tab and pane closure to `gone` instead of a cascade.

Every pre-existing fixture whose first seat is later retired, deactivated or closed now fails. Each task was tested in isolation with scoped filters, and the opt-out (`plan::managers::testing::opt_out`) was applied only to some fixtures. The 35 lib failures and 6 of the 7 integration failures all carry the `node manager <x> cannot be retired|deactivated|moved or closed` refusal, or a `timed out waiting for ... to retire` caused by the closure exemption. Two of the failing tests are new in this epic: `bootstrap::tests::show_seat_appends_manager_line` and `show_cycle_is_store_integrity` from hg-k4l.16. Their first seat silently becomes the node manager, so the expected "none assigned" line and the expected cycle do not hold. The global constraint "Full suite: cargo test" is therefore not met at head.

Composition defect B comes from the new graph.toml writer (hg-k4l.5) and the instruction-source writer inventory guard. `tests/instruction_writers.rs::instruction_source_writers_are_inventoried` fails because `src/plan/managers/mod.rs` (`write_graph`, a raw `put_file` of graph.toml) is a new raw file writer that is not in the inventory. graph.toml is not an InstructionSource path and is written only by plan kinds committed by apply. The fix is to add it to the inventory with that reason, not to weaken the guard.

Interfaces that do agree across clusters:
- `cycle_guard` requires `name` and `teamspace` in `seat.create` detail. Both producers supply them: SeatCreate in core_kinds and `create_effects` in templates/kinds. So `admit` does not refuse application apply plans as malformed.
- The retire guard's effect vocabulary (`seat.retire`, `seat.deactivate`, `runtime.close_tab`, `teamspace.retire`, `runtime.close_workspace`, `clone.retire`, `runtime.close_pane`) matches what core_kinds, templates/kinds and undo/preview emit.
- `DesiredRuntime.node_manager` (reconcile) is the one live answer that classify reads. CascadeMutation re-reads `live_node_manager` at apply time. Both use model::manager, as the key abstractions require.
- The integrity path runs from `unresolved` in ports/store, through bootstrap `seat_reply` and `CommandError::from_store` (daemon registry), then `IpcErrorCode::Integrity`, to `cli::daemon_error` exit 6. It is consistent end to end. Plan-time store errors, Integrity included, still map to `internal` (exit 1) through `PlanError::Store`.
- ORG_KINDS in tests/daemon_composed.rs lists `node_manager_set` but not `manager_edit`. The registration test checks only that the listed keys are present, so it passes. The list is merely incomplete; cluster 17 records this as deferred.

## Deferred OK
- Plan-time store errors, Integrity included, still surface as `internal` (exit 1) through `PlanError::Store`. With `admit` loading every pointer on every plan, one out-of-band dangling pointer makes reparenting plans fail with exit 1 rather than exit 6. The spec scopes exit 6 to seat.resolve, and a follow-up should route plan Integrity through `from_store` (clusters 5 and 9; seam).
- `admit` scans every seat and teamspace record, plus graph.toml, once or twice per plan, and DesiredRuntime::load repeats the scan on every observer pass; this is an efficiency cost only (clusters 8, 9 and 11).
- The apply-side reparent resolves the nearest surviving manager even when nothing reports to the retiring seat, so a seat with an out-of-band dangling manager plans cleanly and then fails at apply; `manager clear` is the remedy (cluster 9).
- When the CascadeMutation apply-time re-check skips the node manager, its runtime stays Present and its occupancy is not ended; the race window is narrow and reopen by planner lookup is unaffected (cluster 8).
- ORG_KINDS in tests/daemon_composed.rs omits `manager_edit`; the presence-only check still passes (cluster 17).
- Drop the stale AWAITING_HG_K4L_3 exemption in the src/cli/daemon_error.rs tests now that hg-k4l.3 has merged (cluster 4).
- Outside Herdr, NoInstance renders the not-in-Herdr line instead of the init hint; this is spec-sanctioned and the exit code is unchanged (cluster 4).
- The show manager line uses "->" where spec §4.12 has the arrow glyph, and render_seat prints "node manager: none assigned" for an unbound caller even when one is assigned (cluster 3).
- The Post-Implementation Notes are empty, and run.md and the profile snapshots are stale; fill and refresh them when hg-k4l.20 lands (cluster 2).
- Cosmetic test hygiene: `admit_stubs_pass` naming, the unused Herdr UnixListener fixtures, the near-vacuous `contains("s")` assertion, duplicated git2 helpers and the SetManager/TestManager duplication (clusters 9, 14 and 17).

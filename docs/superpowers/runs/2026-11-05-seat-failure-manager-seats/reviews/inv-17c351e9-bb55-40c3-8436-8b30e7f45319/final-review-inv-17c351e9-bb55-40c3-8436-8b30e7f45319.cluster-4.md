## Analysis by spec section

### 4.4 condition table (cli::daemon_error)

`classify` matches every `ClientError` variant (NoInstance, NotInHerdr, Unavailable, Remote, Frame, checked against src/daemon/client.rs at head) and every `IpcErrorCode` explicitly, with no wildcard arm, so a new code fails compilation instead of silently falling to exit 1. Row by row: NotInHerdr goes to 2; no-reply conditions (Unavailable, Frame, NoInstance) with HERDR_SOCKET_PATH unset go to 2 with the spec line; NoInstance inside Herdr keeps its existing line, exit 2; Unavailable, Frame, Remote{Unavailable} and Remote{VersionMismatch} go to 5 with the retry text; Remote{Integrity} goes to 6 regardless of in_herdr; everything else goes to 1 as `herdr-graph: <message>`. The `strip_dot` handling avoids "..". `store_failure` renders a local StoreError::Integrity to the exit-6 text and returns None otherwise. Unit tests cover one row per condition, including a real hung-socket read timeout (Frame) and the still-starting and failed-to-start Remote{Unavailable} messages, as 4.4 requires.

The constants EXIT_DAEMON_UNAVAILABLE = 5 and EXIT_INTEGRITY = 6 sit beside EXIT_NO_INSTANCE in src/daemon/client.rs.

### Routing of every daemon-calling command

A grep of src/cli at head for `call_daemon` / `ClientError` shows each daemon caller now goes through daemon_error: ops (list, show, cancel, reassign, check-instruction via a local `call` wrapper), plan (plan.create, both plan.apply sites), request (mutate and list; the StillRunning Remote arm stays in the command ahead of the helper, as 4.4 allows), seat (via `seat_failure`, which composes on top of `classify`), undo (candidates, plan.create, undo.apply, ops.get poll), who, and status's `writer resume`. The remaining direct matches are `status` (Unavailable goes to `direct_status`, the deliberate 4.13 exception) and `session` (the session-report hook spools on any error; documented as exempt in the daemon_error module header). StillRunning as an error code is produced only by src/transcripts (request); the plan flow reports still-running through reply state in `report_apply`, so routing plan errors through the helper loses no exit-3 path.

### 4.13 fallback removal (B1, B14)

who, ops (list/get/check_instruction), request list and undo candidates no longer fall back on ClientError::Unavailable; their direct-read helpers (`Direct`, `direct()`, the fallback closures) are deleted from src/cli. The library functions they called (plan::ops::list_json/op_detail/check_instruction, undo::commands::list_json, transcripts::requests::list_view, threads::who) stay because the daemon handlers use them. tests/daemon_free_reads.rs spawns the binary and asserts exit 5 for who, ops, ops --unresolved, op, check-instruction, request list (two filters), undo --list and undo --json, plus `status` still reading directly and a read outside Herdr exiting 2.

### Seat failure path (B2, B3, B4, 4.4, 4.5)

`seat` maps a failed seat.resolve through `seat_failure`: exit 5 appends the "run /seat again later" sentence, exit 6 the "do not retry" sentence, and 2 and 1 are unchanged. The strings match the spec text. HOOK_PROMPT gains "If /seat fails, follow the skill's failure step.", tested for both the Claude and Codex shapes. tests/seat_exit_codes.rs covers exit 5 (both text and --json), no instance (2) and outside Herdr (2) from the spawned binary. The skill text itself is in the misc cluster.

### show (B9, 4.12)

`show` stays a daemon-free reader. A ShowError::Store carrying StoreError::Integrity (for example a manager-chain cycle from `named_manager_chain` in bootstrap/show.rs) maps to the exit-6 line through `daemon_error::store_failure`; other errors keep the generic path. The manager line itself is rendered in bootstrap/show.rs and the who line in threads (other clusters). The CLI side just prints what they return.

### Unassigned warning (B12, 4.10)

`cli::main` calls `node_manager_warning::warn(&cli.command)` before `run`, which is one module declaration plus one call from main, within the src/cli/mod.rs header rule. `applies` skips init, setup, daemon (all subcommands) and `seat --hook-prompt` (with or without --codex). `warn` returns silently when there is no instance or when the store open, HEAD or `Pointers::load` read fails. `check` warns when a non-retired seat exists and `live_node_manager()` is None, which covers unset, missing and retired node managers. The text is built from NODE_MANAGER_SET_USAGE. Unit tests and tests/node_manager_warning.rs cover: unassigned warns exactly once, assignment silences it, empty graph, dangling id, retired node manager with another live seat, exempt commands, and no instance.

### Residual observations (none blocking)

- The `no_command_matches_unavailable_itself` source-scan guard in src/cli/daemon_error.rs still exempts who.rs, ops.rs, request.rs and undo.rs via `AWAITING_HG_K4L_3`, although hg-k4l.3 has merged. At head none of the four contains `ClientError::Unavailable`, `fn remote(` or `.map_err(remote)`, so dropping the list would pass today. As written, the guard does not protect exactly the files Part C changed.
- `warn` runs `locate_instance` (which may spawn `herdr plugin config-dir` with a 2 s deadline when no instance env var is set) and a full seat/teamspace scan through `Pointers::load` on every invocation. That includes the frequent `session-report` hook. Each command now does this lookup twice. This is a latency cost only, with no correctness impact.
- Outside Herdr, a NoInstance from `request ack/complete` and the other commands now prints the not-in-Herdr line rather than "no instance configured — run herdr-graph init". The exit code is still 2. The spec table sanctions this, but an operator in a plain terminal loses the init hint.
- `status` keeps its fallback only for ClientError::Unavailable. A hung daemon (Frame) or a Remote error still exits 1 through anyhow. This is consistent with status being the exempt operator diagnostic.

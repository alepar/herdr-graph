## What the cluster changes

- `TemplateEdit::plan` collects every seat whose withdrawal outcome is `Retire`, across all applications of the edited template, and appends `reparent_effects(cx.tree, &retiring)` once, after the per-application loop. The preview therefore treats every seat the edit retires as one retiring set (§4.11, B6).
- `ApplicationRetire::plan` appends `reparent_effects(cx.tree, &preview.retire)` after the withdrawal effects (§4.11, B6).
- `member_seat_record` (the stand-in record used for config resolution) gains `manager: None`, following the new `SeatRecord.manager` field.
- tests.rs: the fixture registers the test mutations `SetNodeManager` and `SetPointer`. One assertion now expects the integrity text "not found at the committed revision" from Part A's `unresolved` helper, where it used to expect "missing". New tests cover: the make_plan guard refusing a template withdrawal and an application retire of the node manager (B8); a chained application-retire reparent preview with apply (a and b retire together, c is rewritten past both to nm); and a template-withdrawal reparent preview with apply.

## Trace against the requirement baseline (rows this cluster touches)

- B6 (reparent to the retiring seat's parent): delivered for the two template-side retirement routes. The plan side lists `seat.manager` / `teamspace.default_manager` effects through the shared helper. The apply side goes through `do_retire_seat` (TemplateEdit mutate at kinds.rs:~1249, ApplicationRetire mutate). Both are reachable from `herdr-graph plan template edit` and `plan application retire`. I traced the sequential `do_retire_seat` order for the chained case by hand: either retirement order ends with c -> nm, which matches the preview's final value. The apply-side `reparent` inside `do_retire_seat` sits in plan::managers and is the seam reviewer's to trace.
- B8 (node manager cannot be retired): the templates kinds rely on the single `make_plan` -> `managers::admit` guard. Every effect kind the template kinds emit (seat.retire, clone.retire, runtime.close_tab, among others) is one the guard inspects. The two new tests exercise it through the real plan entry point. Delivered within this cluster.
- B7 (pointer changes only through plans): template retirements change pointers only inside the plan's mutation, through `do_retire_seat`. Delivered.
- B10 (the first seat becomes the node manager; graph templates create the first seat with the node manager role): NOT delivered on the template paths at this head. `git grep first_seat` at head finds callers only in src/plan/core_kinds.rs (`SeatCreate`). src/templates/kinds.rs contains no reference to `first_seat`, `node_manager` or `graph_blob`. So `ApplicationApply` (via `create_member_seat`) and `TemplateEdit` member additions never assign `node_manager_seat` and never add the `graph.toml` blob precondition. On a fresh graph, `application apply <tpl>` therefore creates seats with no node manager, and the unassigned warning follows. That breaks the human request "graph templates just provide default templates which create the first seat with the node manager role" and §4.8's "Every path that creates or resurrects a seat ... goes through one shared first-seat helper". The bead for this work, hg-k4l.24 ("Application apply/hydrate and TemplateEdit additions use the first-seat helper", files src/templates/kinds.rs and src/templates/tests.rs), is still open. S1 only changes "seated" to "created", so no human scope change covers the gap. The shipped `node-manager`/`office` templates (hg-k4l.14, still open; no templates/node-manager or office files exist at head) live outside this cluster (bootstrap/examples) and are the seam/bootstrap reviewer's to trace. Even with them shipped, the row still needs the ApplicationApply assignment from this cluster.

## Other observations

- The preview does not rely on the revs of the rewritten holders (c, r). This matches `SeatRetire` in core_kinds and the shared helper's contract. Apply recomputes reparenting in `do_retire_seat`, so final pointers stay correct even when a holder changes between plan and apply. Only the preview can go stale.
- `retiring` in TemplateEdit is collected only for `Outcome::Retire`. `Gone` and `Keep` correctly add nothing, and `session.replace` replacements do not retire seats.
- I did not rerun the tests in this review. The host has no C toolchain (builds need the ht-build toolbox plus a libz shim, per the task reports), and the review stayed read-only. Pass status rests on the task reports.

## What the cluster changes

- It adds `StoreError::Integrity { holder, field, target, reason }`, which displays as `"{holder}: {field} {target} {reason}"`.
- It adds the free function `unresolved(holder, field, target)`, the single constructor. Its default reason is "not found at the committed revision".
- It adds `StoreError::because(reason)`. On an `Integrity` error it replaces only the reason. On every other variant it returns the error unchanged.
- Two unit tests cover the constructor, the Display text, and the pass-through of `because` on a non-Integrity variant.

## Observations

- The doc comment "Build only via `unresolved`" is a convention, not something the compiler enforces. Fields of a Rust enum variant are always public, so any module can write the literal. The grep above shows the convention holds at head. That is adequate for the spec, which only names a single helper.
- Calling `because` on a non-Integrity error silently discards the requested reason. That is the documented behavior and is tested. Every current caller applies it directly to an `unresolved(..)` result, so no call site can lose its reason.
- The Display text puts holder, field, target and reason in a fixed order. This makes some holders read awkwardly, such as bootstrap's `(seat, "record", seat)` triple ("st_x: record st_x not found ..."). That wording comes from call-site data in the bootstrap cluster, not from this cluster.
- I did not run the tests in this review. Building requires the ht-build toolbox with a libz shim (see the task reports). Building in the caller worktree would also write to its `target/`. The task-1 report records the cluster's tests passing at its own head.

## Code analysis

- Spec §4.8 says every seat-creating or seat-resurrecting path goes through the one first-seat helper. SeatResurrect (core_kinds.rs:1496) and TeamspaceResurrect (core_kinds.rs:797), both in this cluster, never call `first_seat::assignment`. Neither does undo restore. Resurrecting a seat into a graph where every seat is retired and `node_manager_seat` is unset leaves the graph with no node manager and no automatic assignment (hg-k4l.25 open).
- The cycle guard's effect mapping matches every producer of `seat.create` in the tree. Both core_kinds.rs:1003 and templates/kinds.rs:415 carry `name` and `teamspace` in detail, so the guard does not wrongly refuse application or template plans as "malformed". `cycle_from` ignores resolution errors (`while let Ok(Some(..))`), so a pre-existing dangling pointer cannot make the guard refuse unrelated plans. `ManagerEdit` relies on the same tolerance, which keeps `manager clear` usable as the repair path.
- Asymmetry in reparenting: apply-side `reparent` (reparent.rs:70) resolves the retiring seat's nearest surviving manager unconditionally. The preview `reparent_effects` resolves only when some live holder points at the retiring seat. A seat whose own explicit manager dangles out of band, and that nobody reports to, therefore plans cleanly and then fails at apply with an integrity error (Fail::Data). The observed route is lenient and unaffected; `manager clear <seat>` is the workaround.
- `admit` now runs on every plan. `refuse_node_manager_retirement` always loads `Pointers` (all seat and teamspace records plus graph.toml), and the cycle guard loads them again for pointer-relevant plans. One corrupt unrelated seat record now fails every plan with a store error, where some kinds previously did not read it. The cost is two full record scans per plan.
- `NodeManagerSet::mutate` does not re-validate. It relies on relied_on revs and the `graph_sha` in the effect detail to make a recompute against a changed graph differ, which is consistent with spec §4.7. A seat created after planning that points at the old node manager is not covered by relied_on (task 11 already notes this race).

## What the cluster changes

- `DesiredRuntime` gains `node_manager: Option<SeatId>`, filled in `DesiredRuntime::load` from `model::manager::live_node_manager(tree)?`. The reconcile planner (`plan_effects`) never reads it. Its only consumer is `observe::classify` (lines 279 to 331 at head), which uses it to exclude the node manager from cascade grouping. That is a seam into the observe cluster.
- tests.rs adds a test-only `bookkeeping.test_node_manager` mutation and the test `node_manager_with_absent_runtime_gets_tab_and_panes`. The test checks two cases. When the workspace is closed and the node manager's bindings are Absent, `plan_effects` plans CreateWorkspace before CreateTab and also a pane effect. When only the tab is closed, the plan includes CreateTab and no CreateWorkspace.

## Requirement baseline trace (B11)

- B11 ("same tab, stays open, gets reopened if it ever is closed"). The spec (section 4.9) assigns reopening to the existing reconcile planner. Its only precondition is that the observer does not retire the node manager. At head, `plan_effects` reopens any Active seat whose bindings are Absent. It recreates the workspace when needed, then the tab, then the panes. The new test confirms this for both workspace closure and tab closure. Nothing in this cluster is node-manager specific: the test's `assert_eq!(d.node_manager, ...)` only checks the loader. The planner would behave the same for any active seat.
- The production path runs: Herdr closure, then observe classify excludes the node manager from the cascade, then the seat stays Active with Absent bindings, then reconcile reopens it. The middle step belongs to the observe cluster, and the hand-off between them is the seam reviewer's to trace. The observe tests `node_manager_tab_close_is_not_retired_and_reopens` and `node_manager_pane_close_is_not_retired` drive that path end to end. The reconcile half of B11 is delivered at head.

## Test run evidence

The run used a review-owned detached worktree at the head commit. Its target directory was reflinked from the run worktree. The command was `cargo test --lib --locked --offline reconcile::`, run in the ht-build toolbox: 51 passed, 5 failed.
- Failing tests: `retire_after_queued_create_is_obsolete`, `close_effects_predict_induced_closures`, `deactivated_seat_closes_its_tab`, `reactivated_seat_starts_agent_again`, `relaunch_refused_for_dormant_seat`.
- All five panic in the fixture helper `plan()` (src/reconcile/tests.rs:242) on the same guard. One example: "seat deactivate foreman: node manager foreman (st_...) cannot be deactivated; move the role first with herdr-graph plan node-manager set <seat>". - Cause, as observed: in these tests `activate()` creates `foreman` as the first seat on the node. First-seat assignment (B10) makes it the node manager. The section 4.9 `make_plan` guard then refuses to retire, deactivate or retire the last clone of the node manager, which is what the spec requires. The production behaviour is correct. The pre-existing reconcile tests were not updated for the new invariant.
- The new test `node_manager_with_absent_runtime_gets_tab_and_panes` passes on its own. Its `test_node_manager` bookkeeping step is redundant at head, because first-seat assignment has already made `foreman` the node manager. It is harmless.

## Other observations

- `DesiredRuntime::load` now calls `Pointers::load`, which lists every teamspace and every seat, retired and archived included. `load` also walks the teamspaces itself, so each observe and reconcile pass scans the tree twice. This only affects efficiency and does not change correctness.
- `load` now also needs graph.toml to be present and parseable (`read_graph` returns Corrupt "missing" otherwise). The store initialiser always writes graph.toml, so no reachable state should break here. If graph.toml were corrupt, observe and reconcile would now both fail every cycle; before, only graph.toml readers failed. This is acceptable, since it is an integrity condition.

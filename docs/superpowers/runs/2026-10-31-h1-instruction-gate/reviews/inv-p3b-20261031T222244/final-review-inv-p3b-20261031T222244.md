## Seams checked, and how they compose

1. ApprovalGate install (bootstrap) vs relay copy (cli) vs ask-rule prefix. `ask_entries` installs `Bash(herdr-graph apply:*)` plus the absolute-binary form. The Codex rules file uses `prefix_rule(pattern=["herdr-graph","apply"])`. The relay hint in src/cli/plan.rs:69 and the `content write` stub tell agents to run `herdr-graph apply <pl> --confirm <hash> --confirmed-by user-relay`, which both rules match. The only commit senders are `apply` (`mode: relay`, plan.rs:161) and the two `mode: tty` paths (plan.rs:140, undo.rs:127), which both pass through `prompt_terminal`. There is no third commit path that bypasses the prefix rule. Consistent.
2. Hook (cli) vs plan-time cap warnings (plan, templates, kinds_extra) vs renderer (bootstrap). The hook, `cap_warning` in src/plan/instructions.rs:248, src/plan/kinds_extra.rs:509 and src/templates/kinds.rs:1257 all go through `bootstrap::instructions::fit_hook` with the one `HOOK_RENDER_CAP` and the one `PatchedTree`. So the plan warning names exactly the parts the hook later omits. Consistent. The Codex JSON envelope pushing the output past the cap (cluster 5) is the same seam viewed from outside, and the unverified Codex `additionalContext` limit (cluster 1) is the open question there.
3. InstructionSource (store) as the single owner. The renderer (src/bootstrap/instructions.rs:227/231/296), `paths.data` (`classify` in src/bootstrap/mod.rs:114), doctor `instruction_files_check`, InstructionsKind and undo `instructions_inverse` all take paths and file lists from `instruction_source`. No caller builds instruction paths by hand. Consistent with the key-abstractions digest.
4. GraphId (model, store) to global-scope effects (plan) to undo target (undo). `affected[0]` = `gr_<instance_id>` resolves back through `layout::locate`. Cluster 14's probe confirms that global and teamspace undo plan and commit. Consistent. The only cosmetic gap: `Names` shows the raw `gr_` id in undo candidates.

6. Legacy `content write` across clusters. The daemon command and mutation are gone (bootstrap, daemon compose). The writer fails legacy rows with "no mutation registered" (writer). The model keeps the variants. The wiring sweep skips `ContentWrite`. The CLI stub exits 2. The threads notification and the summarizer template no longer mention it. The remaining references at head are all on the hg-45e.11 side: skills/graph/SKILL.md:42, README.md:52, CREATING_NEW_GRAPH.md:70, and the needle at src/bootstrap/tests.rs:1015, which asserts the graph skill still says "content write". That needle and the skill must change in the same commit, or hg-45e.11 goes red.
7. Hydration change (templates) x renderer order (bootstrap) x existing instances. This behaviour only appears once every cluster is merged. New seats no longer get a seeded seat `AGENTS.md`. On an existing instance, every seat hydrated from an inline member still carries the old copy, and the renderer now emits the member text twice: step 3 (member `AGENTS.md`) and step 6 (seat `AGENTS.md`, which renders last and wins). For the shipped summarizer, both copies are pre-H1 text that tells the agent to run `content write`, which now exits 2. So the summarizer pipeline breaks on upgrade until the user runs `plan template edit` and then `plan instructions clear seat <name> AGENTS.md`. The duplicated text also inflates the hook size. Near the cap, `fit_hook` drops general parts (global and teamspace rules first) to keep the stale duplicate, and no plan-time warning fires, because no plan ran. The spec accepts manual migration only behind the §1.5 CHANGELOG note, and that note is absent (cluster 1). This makes the missing note a functional upgrade break, not a docs nicety.
8. Renderer placeholder (bootstrap) vs doctor (daemon). The placeholder for template, member, responsibility and section parts says "see herdr-graph doctor", but doctor scans only InstructionSource scopes. Reachable only through direct git commits (cluster 6). Deferred.
9. Hook bound rule (cli) vs `wants_seat_prompt` (bootstrap). `hook_text` accepts env-resolved `Bound`, while `wants_seat_prompt` is binding-only. This agrees with `seat --instructions` §4.3 and with the seat skill's "same revision" sentence (cluster 3). It is benign, but the spec text differs (cluster 5). Deferred.

11. worktree_dirty notification (threads) vs InstructionsKind's closed file set (store). The notification tells agents to commit any dirty seat-folder file through `plan instructions set`, but that kind rejects data paths, and data files now have no graph write path at all (cluster 12). Undo of a template edit replans through `TemplateEdit`, which now checks every text field in the document, not only the changed ones. A template carrying any pre-existing inadmissible text therefore cannot be undone (Invalid, not repair_required). This fails closed, as the instruction-undo case does in cluster 14. Deferred.
13. Doctor harness_gate (daemon) x setup (bootstrap) x Env (config). The same `config_dir`/`codex_dir` resolvers and the same empty-value semantics are used throughout (clusters 6 and 9). Consistent. The env-to-doctor wiring is exercised only by the open hg-45e.12.
